# Oryn Documentation

## Documentation Architecture and Baselines

This directory contains the component design briefs, cross-cutting architecture specifications, and architecture decision records for Oryn.

### Authoritative Baselines

1. [PRODUCT.md](../PRODUCT.md): Authoritative product baseline governing customer-visible behavior, user experience, permission tiers, autonomy levels, retention defaults, and v1.0 acceptance criteria.
2. [TECHNICAL.md](../TECHNICAL.md): Authoritative cross-component technical architecture baseline defining component boundaries, domain concepts, integration flows, and non-negotiable invariants.
3. [docs/architecture/cloud-inference.md](architecture/cloud-inference.md): Authoritative shared AI inference baseline. All Oryn-owned v1.0 model inference uses cloud-managed APIs through the LiteLLM gateway with zero content retention and US processing; on-device inference is post-v1.0.
### Precedence Hierarchy (TECHNICAL.md §0.3)

1. **`PRODUCT.md` governs first:** Customer-visible scope, safety policies, risk tiers, and acceptance criteria override technical documentation when a conflict arises.
2. **`TECHNICAL.md` governs second:** Cross-component boundaries, authoritative state ownership, communication patterns, and system invariants.
3. **Component design documents govern third:** Internal subsystem architecture, algorithms, and local data choices within component boundaries. Any proposed change to a shared contract or boundary requires an explicit architecture update.

### Nature of Baseline Briefs

Documents in `docs/components/` and `docs/architecture/` represent **baseline briefs**. Established requirements are grounded in `PRODUCT.md` and `TECHNICAL.md`. Pending design questions record open technical decisions and tradeoffs; they are **not** architectural approvals or implementation commitments. The existence of a document does not imply that the component exists in code or is release-ready.

## Detailed Component Specifications

Detailed technical specifications are complete for the following subsystems:
1. **[Desktop Shell](components/desktop-shell.md):** Host runtime, native status adapters, employee controls, visibility leases, and presentation architecture — see [ADR-0001](adr/0001-desktop-runtime-and-presentation.md) and [ADR-0002](adr/0002-desktop-capture-lifecycle.md).
2. **[Native OS Observation Adapters](components/os-observation.md):** Nested worker supervision, inherited byte channels, masked shared-memory snapshots, all-visible multi-window scope with background continuity, source-specific crash containment, and certified managed browser fallback — see [ADR-0003](adr/0003-native-observation-admission-and-isolation.md).
3. **[Browser Extension and Local Browser Bridge](components/browser-extension.md):** MV3 service worker, isolated content scripts, Native Messaging host, shell broker attachment, WebCrypto profile pairing, per-modality arbitration, `declarativeNetRequest` navigation guard, deterministic target resolution, and local action pause — see [ADR-0004](adr/0004-browser-bridge-and-execution-boundaries.md).
4. **[Meeting and Audio Intelligence](components/meeting-intelligence.md):** Process taps (Core Audio / WASAPI), browser offscreen tab capture, LiteLLM live/near-live STT, commitment review, and reminders — see [ADR-0005](adr/0005-cloud-inference-and-private-evidence.md) and [ADR-0006](adr/0006-meeting-capture-and-review-boundaries.md).
5. **[Local Privacy Gate, Evidence Store, and Retention](components/local-privacy-storage.md):** Rust `oryn-privacy-helper`, SQLCipher 4 encrypted partitions, AES-256-GCM chunked media blobs, generation catalog anchored in OS credential store, crash-safe selective purge, 30s volatile memory ceiling when retention disabled, Contract 25 `privacy-context.v1`, signed review attestations, and bounded offline leases — see [ADR-0007](adr/0007-private-evidence-storage-and-retention.md) and [ADR-0008](adr/0008-reviewed-still-image-sharing.md).
6. **[Local Context HUD and Guided Assistance](components/local-context-hud.md):** Unified Rust `oryn-hud-helper` behind a single deterministic reducer, exact-match in-memory guidance index, Contract 25 `privacy-context.v1` (major 1, minor 2) observation and private persistence wire, Contract 20 `shell-hud.v1` presentation over inherited channels, governed cloud semantic inference (`text.reason`), one resumable guide with version pinning, distinct assist plan identity (`ExecutionContextV1`) over common execution rails, and signed offline guidance leases — see [ADR-0009](adr/0009-local-context-guidance-and-assist-boundaries.md).
7. **[Contribution and Synchronization Gateway](components/contribution-sync.md):** User-space Rust daemon `oryn-sync-helper`, encrypted SQLCipher 4 outbox and guidance working set cache, Contract 24 `contribution-sync.v1` reliable delivery over HTTPS/TLS, Contract 3 `guidance-sync.v1` publisher-signed working set synchronization, atomic PostgreSQL intake transactions, Ed25519 review attestations signed with software review key in OS-protected credential storage, idempotent replay, and immediate withdrawal propagation — see [ADR-0010](adr/0010-contribution-delivery-and-guidance-sync.md).
8. **[Identity, Policy, and Authorization Authority](components/identity-policy.md):** Managed authentication via Auth0/OIDC/SAML, typed embedded evaluator in Rust (`oryn-identity-evaluator`), PostgreSQL durable authority with row-level security and transactional authority guards, HashiCorp Vault Transit Ed25519 signing, single-use action fence (`identity_action_fence`), and independent Authority Recovery Journal checkpoint protocol — see [ADR-0011](adr/0011-identity-authority-and-approval-fencing.md) and [schema](architecture/contracts/identity-policy-v1.schema.json).
9. **[Workflow Discovery and Procedure Synthesis](components/workflow-discovery.md):** Conservative hybrid clustering on PostgreSQL/pgvector, cluster-wide compatibility, strict audience conjunction, three-demonstration gate, business-equivalent variants, task-level duration minimization, immutable revision diffs, sanitized suppression rules, acyclic repetition guidance, separate guidance approval and publication staging, and Contract 25 minor 2 amendment — see [ADR-0013](adr/0013-workflow-discovery-evidence-and-review-boundaries.md) and [schema](architecture/contracts/workflow-discovery-v1.schema.json).
10. **[Living Operational Graph and Knowledge Governance](components/operational-graph.md):** PostgreSQL 18 relational authority with recursive CTEs and pgvector cosine, strict 1:1 capability-to-workflow mapping, Playbook Version RFC 8785 body digest, deterministic three-valued logic and UNIQUE decision tables with pairwise disjointness solver proof, transactional guard serialization vs. asynchronous impact analysis, separate central publication vs. HUD qualification with Vault Ed25519 bundle signing, and canonical handoff obligations with separately authorized summaries — see [ADR-0014](adr/0014-operational-graph-knowledge-and-rule-governance.md) and [schema](architecture/contracts/operational-graph-v1.schema.json).
Refer to the resolved architecture decisions and owner-scoped dependencies in each component brief. In accordance with [TECHNICAL.md §14.3](../TECHNICAL.md), cross-cutting foundation agreements (such as identity/policy schemas, version lineage, and cross-component authorization contracts) remain owner-scoped dependencies to be negotiated, rather than invented unilaterally within individual component briefs. No software implementation or physical hardware certification is complete at this documentation phase.
